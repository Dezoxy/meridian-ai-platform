### S098 — Demo claims on kind

**Status:** doing · **Started:** 2026-10-08 · **Finished:** —
**Goal:** put synthetic claims on the local kind cluster, through the Claims
API, so that the adjuster's queue and the claimant's lookup show content
instead of the one claim `make demo` posts. **Written and tested without a
cluster; NOT run on the cluster yet** (hard rule 7).

**Decisions:**

- The owner, 2026-10-08, asked: "Okay can we fill up the admin and non-admin
  side with tenants?" After the words were sorted out (a tenant here is an
  insurer; the pages' people are users) the choice was **"Users, one
  organisation"**: test people to sign in with and seeded claims so the pages
  show content, in one insurer. This step is the claims. The people are the
  sign-in step's (S021, where the realm generator lives); claimants' own
  accounts are S093.
- **A script and a make target, through the API.** `infra/kind/demo-seed.sh`
  and `make demo-seed` post the first `COUNT` claims of
  `data/synthetic/claims.json` (40 by default; at most 47, all golden claims) to
  the Claims API through the edge, with the URL, the body and the kind of
  `traceparent` that `demo.sh` uses. Not through the database and not as a
  Job: a claim posted this way has its audit trail and its triage run, as one
  posted by hand has. Rejected: a Job that writes rows (no audit trail, a
  second path to the tables), and a longer `make demo` (it also waits for
  traces in Tempo, which is slow for forty claims).
- **One at a time, with a pause.** A claim is posted, its state is settled,
  and `PACE_SECONDS` (2) pass before the next. The Claims API answers a post
  after the triage, with the claim's state, so the script reads the state over
  the JSON route of the adjuster's pages (`/adjuster/claims/<id>/proposal`)
  only when the post did not settle it; the states that mean "still being
  triaged" are `submitted` and `triaging`, and the bound is 120 seconds (the
  lease on a triage), after which a claim is counted as "not settled" and the
  run goes on. The pause is there for the gateway's request rate per tenant
  (`tenant-request-rate`), which fails the triage of a claim that comes too
  fast; whether 2 seconds is enough is not measured.
- **The model is simulated.** On kind the Model Gateway runs in replay mode; no
  model is called and nothing is billed. The contract for this step spoke of
  answers "from recordings"; that is the evaluation's replay of a real model
  (CI), not kind's, so the help line and the README say simulated. A claim
  whose triage needs the model's answer is referred to a person, which fills
  the adjuster's queue.
- **Safe to run twice.** The 409 "already has a triage proposal" is a skip, and
  "exists with a different submission" is counted apart and named by its ID.
  The two other 409s of the API are handled too: "being triaged" is waited for
  and "triaged five times" is counted apart (the contract named two). A claim
  whose triage failed is triaged again by the next run, because the API takes a
  `triage_failed` claim again.
- **A failed triage is counted and shown.** It does not stop the run. The exit
  status is non-zero only when the edge cannot be reached, a post is refused
  for any other reason (the run stops there, after the summary), or no claim
  could be posted; a second run that skips everything exits 0.
- **The refusals before anything is posted.** The Docker engine must be local,
  the cluster must answer through this checkout's credentials, another
  checkout's hold on the cluster stops it unless `TAKE_CLUSTER=1` (it reads the
  record and never writes it), under 2,500 MB of available memory stops it with
  the figure, and so does a running container whose name has `pytest-db` or
  `pytest-redis` in it (the machine is small and shared). `demo.sh` itself
  never reads the holder record; `make demo` inherits the check from `make
  deploy`, which `make demo-seed` does not run.
- **It decides nothing.** Referred claims wait for a person.
- **What it leaves changed.** The scheduled sweep reads the claims, so the six
  values of `make smoke`'s second sweep line change. From a reading of
  `smoke.d/07-sweep.sh` (not a run): the line asserts that each of the six
  series has a sample in the last 15 minutes and compares no value, so seeded
  claims cannot make it fail. The contract said to stop and report if they
  could; they cannot.
- **Not here:** a second insurer, a sign-in, claimants' accounts, the cast of
  test staff (S021), a reset of the claims (they and their audit rows are not
  deleted by design), and a change to `demo.sh`, the Claims API, the chart, the
  image or the synthetic data.

**The first run on kind: what was open before it (2026-10-08, the worker
session).** Written down before the advisor was asked and before any command
changed the cluster:

1. **From which tree.** The cluster's checkout is moved, detached, to this
   branch's tip, and nothing is deployed again: between the commit the
   cluster was deployed from and the tip, only this step's script, the
   Makefile's target and documents differ. Rejected: `make deploy` first
   (it would build nothing new and only rewrite the holder record).
2. **Who holds the cluster.** The record names S021, whose worker has
   finished. `make demo-seed` only reads the record, so it runs with
   `CLUSTER_HOLDER=S098 TAKE_CLUSTER=1` and the record stays as it is.
3. **A smoke run before the seed as well as after it**, so that a line that
   fails afterwards can be told from one that failed already.
4. **The limits that can fail a triage are three, not one.** The gateway
   applies the tenant's limits in replay mode too (`claims-triage`: 10
   requests in 10 seconds, 10,000 tokens a minute, 300,000 tokens a day).
   The contract and the README name only the first. The second fails a
   triage as the first does (`tenant-token-rate`). The third
   (`tenant-token-budget`) would also fire `MeridianTenantBudgetUsedUp`,
   which fails `make smoke`'s "no Meridian alert is firing" line for a
   quarter of an hour, and would refuse every triage until midnight UTC.
   So the first run is a probe, `COUNT=3 PACE_SECONDS=5`; the tokens one
   triage uses and what the day has used are read from the gateway's own
   figures; the pause for the forty is computed from that, and the forty
   are not posted if the day's budget does not hold them. Rejected: forty
   at 5 seconds at once, as the card proposed before the two other limits
   were read.
5. **The default pause** (2 seconds) and the README's advice (5) are
   changed in this pull request if the probe shows them wrong.
6. **Claims 41 to 47 stay unposted** on this cluster, so `make demo` still
   finds a claim there.
7. **`docs/demo.md`** gets its sentence about `make demo-seed` in this
   pull request (the follow-up below), not a backlog row.

**Advisor:** the implementer consulted once, before writing: it fixed that a
post is synchronous (the 201 carries the state, so the route is read only when
the post settled nothing), that the sweep's findings line asserts the presence
of its six series and not their values, that the static tests which read every
script of `infra/kind/` allow only `kctl` and one holder check, and the tests'
rig. The worker session, 2026-10-08, once, at the design of the first run
(before any command changed the cluster; the seven points above were written
first). It changed four things: the tenant kind triages under was read from
the settings instead of assumed (`claims-triage`, the default of
`MERIDIAN_TENANT`); the month's cost limit was added as a fourth limit and
ruled out (the replay deployments are priced at zero in `models.yaml`); the
figures are read as `make smoke` reads its own (Grafana's datasource proxy,
and two read-only `SELECT`s as smoke's database checks run theirs), with
the calls by outcome and reason beside the tokens; and the static tests of
`infra/kind/` that `main` added since the branch was cut went into the gates.

**The infra review (one reviewer, before the first run):** no CRITICAL. The
script reaches only the local cluster; its contact with the cluster is two
reads and `docker ps`, the rest is HTTP. HIGH: the default pause of 2 seconds
would fail triages, and the binding window is the tokens of a minute, not the
requests of ten seconds (measured below; the default is 10 since contract
SD2). MEDIUM, all three built in SD2: a `curl` failure in the middle of a run
ended it with no summary and the wrong hint; an answer the script does not
know had up to 200 characters of its sentence printed; the hint after a
failed triage named one window of two. LOW, not built: `|| break` after
`post_claim` switches `set -e` off inside it (every failure path there is
explicit today), and the edge's URL is not tied to the cluster the checks
read (as in `demo.sh`). The review also answered what a seed can make `make
smoke` say: a rate refusal fails a triage and fires no alert; a used-up
budget would fire `MeridianTenantBudgetUsedUp`.

**The runs on kind (2026-10-08, the cluster's checkout at this branch, the
holder record left naming S021, whose worker had finished).**

- **Before:** all pods Ready; `make smoke` with the sign-in switch on: 62
  PASS, 0 FAIL, 79 s. The sweep's findings were all 0.
- **The probe, `make demo-seed COUNT=4 PACE_SECONDS=10`:** exit 0 after
  11 s. `CLM-0001` and `CLM-0002` were skipped (already approved, from
  earlier runs of `make demo`: the skip was seen on a real cluster),
  `CLM-0003` posted and `documents_requested`, `CLM-0004` posted and
  `awaiting_adjuster`.
- **What a triage uses, from the gateway's ledger** (`gateway.usage`, read
  only): the triage that asked the model made 5 calls (4 embeddings and 1
  chat), reserved 1,265 tokens and was charged 594, all within 0.17 s; the
  one the rules settled made 4 calls and reserved 43. The day's counter
  stood at 6,400 of 300,000 tokens and the month's cost at 0 (replay is
  priced at zero), so neither budget is near.
- **What that makes of the pause.** Ten requests in ten seconds hold two
  claims, so at 2 seconds four claims' twenty calls meet in one window
  (`tenant-request-rate`); 10,000 tokens a minute hold seven claims that
  ask the model, so at 5 seconds eleven meet in one minute
  (`tenant-token-rate`). At 10 seconds six claims fall into a minute (7,590
  tokens) and one claim's calls into ten seconds. The refusals at 2 and at
  5 seconds are computed from these figures and were not provoked.
