### S097 — The plan in files

**Status:** doing · **Started:** 2026-10-08 · **Finished:** —
**Goal:** Give each step's Part C section and each change-log entry a file of
its own, so that two sessions no longer edit one 24,000-line file, and end the
hand-kept plan version, which two pull requests took in one hour.
**Decisions:**

- The owner, 2026-10-08, asked how to cut the repeated runs that remain after
  the CI speed-up (both sessions append to one change log and edit the same
  tables of one file, and each collision costs a hand merge and a CI round),
  and chose **"Change log and step sections"** from three options (change log
  first, recommended; change log and step sections; not now).
- The owner, the same morning, on what replaces the version: **"Pull request
  number (Recommended)"**. A change-log entry is named for its pull request's
  number; the plan has no `v0.NN` after the move. Offered beside it: keep
  `v0.NN` and rename at collisions; no stored number.
- The owner, on the development base's plan template: **"Yes, after Meridian
  (Recommended)"**. Meridian moves first; the base's template and check follow
  in a pull request there. That pull request is not this one.
- The owner, on telling the other session: **"I message it, facts only
  (Recommended)"**: one message before this pull request opens, with the date,
  the layout and how to port an open branch.
- **Layout.** `docs/plan/steps/S0NN.md`, the Part C section byte for byte with
  its heading first; `docs/plan/changelog/`, the list item byte for byte. The
  plan keeps its top, Part A, Part B and Part D; Part C is a paragraph, the
  template and an index table (step, title, file) in the old order; Part E is a
  paragraph.
- **Blank lines** belong to the file before them: a section runs from its
  heading to the line before the next heading, an entry from its `- **` line
  to the line before the next entry. Part E had no blank line between entries.
- **Names.** An entry labelled `v0.N` is `v0.NN.md`, the minor padded to two
  digits (98 entries, `v0.01.md` to `v0.98.md`; a minor of three digits is
  written as it is). An entry of a pull request is `pr-NNNN.md`, four digits,
  and its first line starts `- **#N, date:**` with the number unpadded.
  `pr-XXXX-<step>.md` with the label `#XXXX` stands in until the pull request
  has a number.
- **The index keeps the old order, not the number order.** Part C was never in
  number order (S040 follows S008, S037 follows S077), and the proof is that the
  files concatenated in the index's order equal the old Part C. The check
  therefore holds the index and the folder to the same set of steps, once each,
  and does not sort them.
- **The placeholder** is refused only under CI (`GITHUB_ACTIONS=true`): on a
  machine `make docs` passes and prints a note, so the pull request can be
  opened before the file is renamed; the first CI run then fails until the
  rename is pushed. The simpler alternative, a flag in the Makefile, would
  have made `make docs` weaker for good.
- **The new checks are a script of their own**, `scripts/check_plan_files.py`,
  which `make docs` runs after the documents check. `check_docs_consistency.py`
  is on the file-size ratchet at 828 lines, a copy of development-base's, and
  growing it would have meant raising an entry that may only be lowered. The one
  change to it, in place and without a new line, is that `check_docs_index` no
  longer demands a link from the docs index to each of the 175 files under
  `docs/plan/` (the plan's index and `check_plan_files.py` own their reach).
- **The links** after the move are fixed by `plan_split.py --fix-links` after
  the proof, by resolving each relative target: it gets `../../` in front when
  it names a file that exists from `docs/` and not from `docs/plan/steps/`, so a
  second run changes nothing. Five links changed; none pointed into the plan by
  an anchor (there was no `meridian-plan.md#…` link anywhere).
- **The re-run** after more plan edits reach `main`: `plan_split.py OLD`,
  `--check OLD`, `--fix-links`, `--words`, `--check OLD --fixed`, with `OLD` the
  plan of the newer `main`. `--words` makes the plan's edits of wording (the
  status block, Part A's steps 3, 6 and 7, "Numbers are taken late", the cluster
  holder paragraph and "Before pushing" as eight exact replacements, each of
  which must match once) and adds S097's row to Part B after S095's. What
  stays by hand is in the pull request's description.

**Advisor:** the implementer consulted twice. Before building (the design): it
