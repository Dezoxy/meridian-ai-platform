# Follow-up backlog: the open rows

Follow-ups that no step's "done when" covers, and that are not closed.
This is the backlog of [the plan](../meridian-plan.md) (its Part B,
"Follow-up backlog"); until 2026-10-08 it was one table in that file
(S100). The closed rows are history, in
[backlog-closed.md](backlog-closed.md). The "No step yet" lines in the
step files are history too; this table is current.

- **Home** is the step that will take the row. It is a proposal until
  that step opens and takes the row into its own "done when". Since
  2026-10-06 every open row names a step (the owner's request; S068 to
  S076 were made for the rows that had none).
- **A new row** goes at the end of this table, in the pull request that
  found it, and names its home: a step that exists, or a new row in the
  plan's "Backlog steps" added in the same pull request.
- **A row that closes moves**, whole, to the end of the table in
  `backlog-closed.md`, in the pull request that closes it, with its
  status rewritten to start `closed by` and the step (or `done`). A row
  closed in part, or for one case only (`closed in part`, `closed for`),
  stays here and says what is left. `make docs` holds each row to its
  file by the first words of its status, read after a struck-through
  beginning.
- **The rows are as they were written**, in their old order. "Below" and
  "above" in a row mean the one table of that time, so the row meant may
  be in the other file; a row number in a test's docstring ("backlog row
  878") was a line of the plan file then.
- The table was rebuilt on 2026-10-03 from every "No step yet" line in
  S041 to S049. The items a later step could have closed were checked
  against the code that day; the rest stand as their step recorded them.
